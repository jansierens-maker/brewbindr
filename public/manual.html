Getting Started

What is BrewBindr? All users

BrewBindr is a web application for home and hobby brewers. It runs in your browser on desktop and mobile — no installation required. Your data is stored in the cloud and syncs in real time across all your devices.

Core features

  • AI recipe generation — describe a beer in plain language and get a complete recipe in the BeerJSON format.
  • Brew log tracking — record your brew day from mash temperatures through fermentation gravity to bottling.
  • AI tasting analysis — get feedback comparing your tasting notes to the recipe's original specifications.
  • Ingredient library — manage your own fermentables, hops, cultures, and miscellaneous ingredients.
  • Stock management — optional inventory tracking with visual "glass fill" indicators.
  • BeerXML support — import and export recipes in the industry-standard format used by most brewing software.
  • Team breweries — brew together: invite members with roles from taster to brewmaster.
The interface is available in English, Dutch, and French. Switch languages any time under System → Settings.
Getting Started

Accounts & sign-in All users

You can browse BrewBindr without an account, but most features require signing in.

Guest mode

Without an account you can explore the public recipe library, browse ingredients, and open Settings and Help. Locked items in the sidebar show a icon — clicking them opens the sign-in dialog.

Creating an account

Click "Create account" at the bottom of the sidebar.
Enter your e-mail and a password. If you received a brewery invite code, enter it during sign-up — you'll automatically join that brewery with the role attached to the invite.
Confirm your e-mail if prompted, then sign in. Your personal brewery workspace is created automatically.
Signing in on a second device? Your recipes, logs, and stock sync live — changes appear on both screens without refreshing.

Brewer's Guide

Recipes & AI generation Brewer

Recipes live in two places: your Brewery (private, yours and your team's) and the public Recipes library (shared with everyone). Recipes are stored internally in the modern BeerJSON format.

Creating a recipe with AI

Open Brewery → New recipe.
Describe the beer you want in the prompt field — style, ABV, bitterness, special ingredients. For example: A sessionable Belgian blond, ~5.5% ABV, spicy yeast character, 20 L batch.
Generate. The AI (Google Gemini) returns a complete recipe: fermentables, hops with additions, yeast culture, mash steps, and target values (OG, FG, IBU, colour).
Review and adjust. Every field is editable — treat the AI output as a strong first draft, not gospel. Then save it to your brewery.

Manual recipes

You can also build a recipe from scratch: add fermentables, hops, cultures, and misc ingredients from your library, define the mash profile, and set batch parameters. Vitals like estimated OG and IBU are calculated as you type.

Every recipe has a print view — a clean brew-day sheet you can print or save as PDF and take to the kettle.
Brewer's Guide

Brew logs Brewer

A brew log turns a recipe into an actual batch. Each brew moves through four phases, and the log follows along — the active tab switches automatically as you advance the batch status.

1. Brew day
Mash, boil, actual OG, volume in fermenter
2. Fermentation
Gravity readings, fermentation temperature
3. Lagering
Conditioning period
4. Bottling
Packaging, carbonation, final volume

What to record

  • Brew day: actual original gravity (OG) and the volume that went into the fermenter. Your recipe's mash profile is shown alongside as a checklist (step temperature, duration, type).
  • Fermentation: gravity measurements over time and fermentation temperature. The log estimates attenuation and current ABV from your readings.
  • Dates: phase-transition dates are filled in automatically when you change status (e.g. moving to "fermenting" stamps the fermentation start date), but remain editable.
Consistent gravity readings during fermentation give you an honest picture of attenuation — and better AI tasting feedback later, since the analysis compares actuals against recipe targets.
Brewer's Guide

Tasting notes Brewer

Once a batch is bottled and conditioned, record how it actually tastes. A tasting note scores the beer on dimensions such as aroma and flavour, plus free-text comments.

AI tasting analysis

Write your comments — be specific: "banana esters dominate, bitterness lower than expected, slightly thin body".
Click Analyze . The AI compares your description against the recipe's specifications.
Read the feedback: likely causes for deviations and concrete suggestions for the next brew of this recipe.
The analysis button is only active once you've written comments — scores alone aren't enough for the AI to work with.

Stock management Brewer

Stock is an optional feature — enable it under Settings → Stock management and a "Stock" item appears in the Brewery section of the sidebar.

The Stock view lists every stockable ingredient in your library (fermentables, hops, cultures, misc) with the amount you have on hand. Each ingredient shows a glass indicator: a beer glass that fills according to your remaining stock. Try it:

Working with the view

  • Filter by ingredient type (fermentables, hops, cultures, misc) or search by name.
  • Switch layout between a card grid (with full glass indicators) and a compact table.
  • Update amounts directly from the view when you buy or use ingredients.

Ingredients you add are private to you and your brewery. When you build recipes, you pick from this library — so a well-maintained library makes recipe creation fast.

You can submit ingredients or recipes to the public library. Submissions are held for review and only appear publicly after an admin approves them (see Submissions).

Brewing installation Brewer

Describe your physical equipment so recipes and calculations match reality. The view has two tabs: Equipment and Mash profiles.

Equipment profiles

An equipment profile defines your batch size, mash efficiency, trub loss, and the vessels in your setup (with volume, heating type, and pump). Start from a preset and tweak, or build a custom profile:

Mash profiles

Define reusable mash schedules (step temperature, duration, type) — single infusion, step mash, decoction. Attach a mash profile to a recipe and it appears as the checklist on your brew-day log.

Equipment and mash profiles are shared with your brewery, so the whole team brews against the same setup.
Brewer's Guide

Import & export Brewer

BrewBindr speaks BeerXML, the de-facto exchange format of brewing software (BeerSmith, Brewfather, Brew Target, and others).

Importing

Open Brewery → Import. You must be signed in.
Select a file — .xml or .beerxml, up to 10 MB. Files can contain recipes or ingredient collections.
Review the result. Imported recipes land in your brewery; imported ingredients in your library.

Exporting

Recipes can be exported back to BeerXML from the recipe view — handy for backups or for sharing with brewers on other software. Brewing installation data (equipment) also travels via BeerXML.

Brewer's Guide

Team & roles Brewer

Every user belongs to a brewery — a shared workspace. Brew alone in your own brewery, or invite others to collaborate. Each member has one of four brewery roles:

RoleTypical rights
AdminFull control: manages members, invites, and brewery settings.
BrewmasterManages recipes, equipment, and brews for the whole brewery.
BrewerCreates and edits recipes, logs brews, updates stock.
TasterViews recipes and brews, adds tasting notes.

Inviting members

From the Team view, generate an invite code tied to a role. The invitee enters this code when creating their account and joins your brewery with that role automatically. Invite codes have an expiry date.

Settings All users

Under System → Settings you tailor BrewBindr to your habits:

  • Unit system — metric (litres, kg, °C) or imperial (gallons, lb, °F). Applied everywhere, including brew logs.
  • Colour scale — SRM or EBC for beer colour values.
  • Stock management — toggle the Stock feature on or off (see Stock).
  • Language — English, Nederlands, or Français.
  • Account — see who you're signed in as, and sign out.

Preferences are stored with your profile, so they follow you across devices.

Admin Guide

Reviewing submissions Admin

Users can submit recipes and ingredients to the public library. Nothing goes live without review: submissions queue up in the Admin view under Pending Submissions.

Open the Admin view. Each pending item shows its type (recipe / ingredient), name, and who submitted it.
Assess quality: is the data complete and plausible? Are names sensible? No duplicates of existing public entries?
Approve to publish it to the public library, or Reject to discard it. The action is immediate.
Approved content is visible to every user, including guests. Review carefully — there is no second moderation step.
Admin Guide

Demo data & backups Admin

Demo data

The Import demo data button loads a curated set of sample recipes and ingredients. Use it to populate a fresh instance for testing, or to give new users something to explore before they've built their own library.

JSON backup & restore

  • Export downloads a full JSON backup of the application data.
  • Restore uploads a previously exported JSON file and reinstates its contents.
Take a JSON export before large operations (bulk imports, demo-data loads) so you can roll back if something goes wrong. Note that Supabase itself is the primary datastore — JSON backups complement, not replace, database-level backups.
Admin Guide

Self-hosting & configuration Admin

BrewBindr is open source. To run your own instance you need Node.js 18+, a Supabase project (auth, database, realtime), and a Google Gemini API key for the AI features.

Clone and install:
git clone https://github.com/jansierens-maker/brewbindr
cd brewbindr
npm install
Configure a .env.local file:
NEXT_PUBLIC_SUPABASE_URL=your_supabase_project_url
NEXT_PUBLIC_SUPABASE_ANON_KEY=your_supabase_anon_key
GEMINI_API_KEY=your_gemini_api_key
Set up the database: run the SQL schema from the repository README in the Supabase SQL editor. It creates the tables, the profiles table with roles, and the row-level security (RLS) policies.
Run it: npm run dev for development, npm run build for a production build. The reference deployment runs on Vercel.

Application roles

Besides brewery roles, profiles carry an application-level role: user or admin. Only admin profiles see the Admin view. Promote a user by updating their row in the profiles table.

Data isolation is enforced by Supabase RLS policies, not by the frontend. If you modify the schema, verify the policies still restrict each brewery's data to its members.
